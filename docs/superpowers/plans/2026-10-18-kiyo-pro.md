# Kiyo Pro Windows Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recognize and configure Kiyo Pro cameras on Windows through the existing CLI and tray/editor, including opt-in live preview and preview-only resolution/FPS selection.

**Architecture:** Keep HID discovery, `Device`, and `Transport` intact. Add a separate camera API in `secbird-core`, backed by a COM-owning Windows worker, then integrate camera identities into the existing profile, CLI, and tray flows. Use browser-native `getUserMedia` to deliver preview frames directly to a `<video>` element; do not add a video streaming service.

**Tech Stack:** Rust stable, existing serde/serde_json and windows-sys dependencies, target-specific `windows` bindings for DirectShow/KS/COM, browser MediaDevices/MediaStream APIs, Node's built-in test runner for isolated preview logic.

**Spec:** `docs/superpowers/specs/2026-10-18-kiyo-pro-design.md`

## Global Constraints

- Support Windows 10/11; keep existing non-Windows core/CLI builds functional.
- USB VID:PID is `1532:0E05`; no other camera models are enabled.
- No replacement HID backend, service, custom driver, or Synapse dependency.
- No firmware checks/flashing, photo capture, recording, or microphone access.
- Discovery/reporting/profile application never start preview.
- Saved settings are not represented as hardware readback.
- Only explicitly saved camera controls are replayed; no invented defaults or automatic device-flash save command.
- Preview format choices apply only to the preview session, never other applications or device profiles.
- No automatic preview restart after disconnect/reconnect.
- Preserve existing Host, Origin, and session-token checks.
- Hardware support remains unverified until the documented physical-camera checklist passes.

## Review Focus

1. Two identical cameras: require an unambiguous backend selector and explicit browser preview-source selection; test in Tasks 2, 4, and 6.
2. Stop/device-switch while permission acquisition is pending: stop late-arriving tracks rather than resurrecting preview; test in Task 6.
3. Partial FOV failure/disconnect: abort that sequence, preserve error context, and do not record successful completion; test in Tasks 1 and 3.
4. Imported profile contains unrelated peripheral fields: a camera applies only camera settings, and HID never applies camera settings; test in Task 3.
5. Worker initialization failure or malformed KS metadata: visible error, bounded message backlog, no panic or unchecked buffer cast; test in Task 2.
